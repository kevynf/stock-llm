# StockLLM Design System

[English](design-system.en.md) · [简体中文](design-system.md)

StockLLM is a desktop-first personal investment research tool. Its interface is stable, compact, scannable, and traceable; it does not imitate a professional quantitative-trading terminal.

## Component Foundation

- All foundational UI components come from the official [shadcn/ui](https://ui.shadcn.com/) registry.
- The project uses the `base-nova` preset, Base UI primitives, and the official default `neutral` theme.
- Sidebar, Button, ToggleGroup, Select, Input, Card, Table, Tabs, Badge, Alert, Empty, ScrollArea, Tooltip, Separator, Skeleton, and Spinner must not be reimplemented locally.
- `frontend/src/components/ui/` contains only official files generated by the shadcn CLI; their visual styles are not edited manually.
- TanStack Query and Table handle data requests and table models only. Visible table structure uses shadcn Table.
- Lightweight Charts renders market charts, and Lucide is the icon library configured by shadcn.
- Business components compose data and page flows, such as candidate tables, research chat, and price charts. They must not become a second foundational component library.
- For new requirements, search and add an official component through the shadcn CLI before considering a custom alternative.

## Official Defaults

- Typography uses Geist, the preset default.
- Border radius uses `radius: default` and is not overridden in business CSS or business `className` values.
- Colors use neutral semantic tokens; the project does not maintain a custom palette.
- Borders, shadows, hover, selected, pressed, focus, and disabled states use built-in component behavior.
- The application currently enables dark mode only, without rewriting the official dark tokens.
- Component font size, line height, control height, and internal padding use official defaults.

## Page Structure

- Sidebar owns desktop navigation and `collapsible="icon"` behavior. The official icon rail remains visible when collapsed.
- Headers and page bodies share the same horizontal spacing; page bodies do not define a separate maximum width.
- The selection view uses a fixed parameter panel and a scrollable results area. In short windows, parameter content scrolls while the primary action stays fixed at the panel bottom.
- Research history, watchlists, and candidate lists consistently use `Card + Table`.
- In the stock summary, security information takes the primary left-side space while search and provenance sit on the right.
- Pages do not nest decorative cards. Cards are reserved for independent tools, tables, results, and settings.

## Interaction

- Interactive states use built-in shadcn behavior. CSS must not simulate button presses, sliders, select arrows, or focus rings.
- Icon-only commands use Button `size="icon"` with a Tooltip and `aria-label`.
- Button icons use `data-icon`; business code does not set icon dimensions.
- Use ToggleGroup for two to five mutually exclusive levels, Select for predefined long lists, and Tabs for page views.
- Forms use `FieldGroup + Field`; actions embedded in an input use InputGroup.
- SelectItem belongs inside SelectGroup, and TabsTrigger belongs inside TabsList.

## CSS Boundaries

### Constrained Space and Overflow

- Flex and grid content columns must be shrinkable. Business containers use `min-w-0`, and pages must not create global horizontal scrolling.
- Navigation, status, numeric, and button labels stay on one line. Variable names use truncation with a `title` or Tooltip for the full value.
- Descriptions, sources, evidence, errors, news, AI replies, and tool traces may wrap. Continuous URLs and evidence IDs use safe word breaking.
- CardHeader CardAction uses at most half of the title container and must not displace the title or description.
- Tables retain readable minimum column widths and scroll horizontally inside the shadcn Table container. Long reasoning cells may wrap without compressing action columns.
- TabsList remains one line and scrolls internally when needed instead of wrapping into irregular rows.
- Toolbars and CardFooter may wrap when actions accumulate. Icon buttons, status badges, and fixed-size controls must not shrink or deform.
- Multi-column business layouts collapse to one column at desktop window breakpoints. Responsive layout may move content but must not hide evidence or key actions.

Outside the tokens generated by shadcn initialization, `frontend/src/styles.css` is limited to:

- stable application and scroll-region dimensions;
- page-level grids, column widths, and spacing;
- the price-chart container;
- layout degradation at narrower desktop widths.

Business CSS must not define or override colors, typography, radius, shadows, borders, or interactive states for Button, Input, Select, ToggleGroup, Tabs, Badge, Card, Table, Sidebar, or navigation.

## Acceptance Criteria

- Pages do not create global horizontal overflow.
- Collapsing the sidebar retains icons and can be reversed.
- Header and body content keep matching horizontal boundaries.
- At `1280×720`, the start-research button remains fully visible and parameter content can scroll.
- Every foundational control traces back to an official shadcn-generated file.
- Business source code does not depend on Mantine or contain a custom foundational control library.
- The browser console has no application warnings or errors, and the production build and TypeScript checks pass.
